# Portomlægning: SFTP 22222 → 9022, reverse-SSH 22022 → 9222

**Beslutning (Peter, 2026-10-01):** Alle porte, TimeLapse eksponerer offentligt, skal ligge under TCP 10000.
2222 var oprindeligt foreslået, men den er reserveret til en anden produktionsapplikation (`deploy/PORTS.md`), så valget blev 9222/9022.

| Funktion | Gammel port | Ny port | Lytter på Headend | Konfigureres for Edge via |
|---|---|---|---|---|
| Reverse-SSH-tunnel (`timelapse_tunnel`, dedikeret sshd) | 22022 | **9222** | `dk.froekjaer.timelapse-tunnel-sshd` (`/etc/ssh/timelapse-tunnel/sshd_config`) | System Administration → enhed → SSH tunnel → *Primary* (`device_config.ssh_tunnel.primary`) |
| SFTP-upload (`sftp_*`) og legacy-tunnel-brugeren `tunnel` | 22222 | **9022** | launchd-socket `com.openssh.sshd-2222` (`/Library/LaunchDaemons/ssh-2222.plist`) + `Match ... LocalPort` i `/etc/ssh/sshd_config` | System Administration → `sftp_port` (global setting) |
| API/UI | 8443 | 8443 | nginx | uændret |

Uændret og kun lokalt på Headend: 8000, 8080, 5432, 5514, 11434 og tunnel-endepunkterne 2201/2204.

## Princip: dobbelt-lyt, flyt Edges én ad gangen, ryd op til sidst

Headend lytter på **både gammel og ny port**, indtil alle Edges er flyttet og har kørt stabilt.
Edge-konfiguration leveres over API'et (8443), som ikke berøres. Går en Edge i stå på en ny port, kan den derfor altid rettes tilbage via System Administration.

**Host-nøgler:**
- Tunnel-sshd'en har en dedikeret, fastlåst nøgle (`SHA256:TwExDmMYpnXX+qK/ZrLwpN2rb8bQiP/FLHKOkfTdbP4`).
- SFTP bruger Headends system-nøgler og har `RejectPolicy`, så der er ingen blind tillid.
- Hver Edge skal derfor have `known_hosts`-linjer for de nye porte **før** den skiftes. `deploy/edge/add_known_hosts_port.sh` tilføjer dem kun, hvis nøglen på den nye port er identisk med den fastlåste nøgle på den gamle port.

## Trin 0 — før kode-deployet (vigtigt)

Kodeændringen (PR "ports below 10000") ændrer **standardværdien** for `sftp_port` fra 22222 til 9022.
Hvis `sftp_port` ikke er sat eksplicit i databasen, ville et deploy straks sende alle Edges til 9022 uden `known_hosts`, og SFTP-upload ville stoppe. Sæt den derfor eksplicit først:

```bash
psql -U timelapse -h localhost timelapse_db -c "SELECT key, value FROM settings WHERE key IN ('sftp_port','sftp_enabled','sftp_host')"
psql -U timelapse -h localhost timelapse_db -c "INSERT INTO settings (key, value) VALUES ('sftp_port','22222') ON CONFLICT (key) DO UPDATE SET value='22222'"
```

Notér `sftp_host` (bruges i trin E1) og om `sftp_enabled` er `true`. Hvis SFTP er slået fra, er SFTP-delen ikke tidskritisk.

## Trin H — Headend lytter på de nye porte (Peter, sudo)

**H1. Tunnel-sshd: tilføj Port 9222 (eksisterende tunneller bevares).**

```bash
sudo cp -p /etc/ssh/timelapse-tunnel/sshd_config /etc/ssh/timelapse-tunnel/sshd_config.bak-20261001
sudo perl -0pi -e 's/^Port 22022\n/Port 22022\nPort 9222\n/m' /etc/ssh/timelapse-tunnel/sshd_config
sudo /usr/sbin/sshd -t -f /etc/ssh/timelapse-tunnel/sshd_config && echo CONFIG-OK
sudo kill -HUP "$(sudo cat /etc/ssh/timelapse-tunnel/sshd.pid)"
```

SIGHUP får sshd til at genindlæse konfigurationen og binde de nye porte. Etablerede tunnel-sessioner overlever.
Brug **ikke** `launchctl kickstart -k`: det dræber hele jobbet, inklusive de aktive Edge-tunneller.

**H2. SFTP-socket: lyt på både 22222 og 9022.**

```bash
sudo cp -p /Library/LaunchDaemons/ssh-2222.plist /Library/LaunchDaemons/ssh-2222.plist.bak-20261001
sudo plutil -replace Sockets.Listeners -json '[{"SockServiceName":"22222"},{"SockServiceName":"9022"}]' /Library/LaunchDaemons/ssh-2222.plist
sudo cp -p /etc/ssh/sshd_config /etc/ssh/sshd_config.bak-20261001
grep -q 'LocalPort 9022' /etc/ssh/sshd_config || sudo perl -0pi -e 's{(^Match [^\n]*LocalPort 22222\n(?:(?!Match )[^\n]*\n)*)}{ my $b=$1; (my $c=$b) =~ s/LocalPort 22222/LocalPort 9022/; $b.$c }gme' /etc/ssh/sshd_config
grep -n 'LocalPort' /etc/ssh/sshd_config
sudo /usr/sbin/sshd -t && echo CONFIG-OK
sudo launchctl bootout system/com.openssh.sshd-2222; sudo launchctl bootstrap system /Library/LaunchDaemons/ssh-2222.plist
```

**NB:** `Match ... LocalPort` accepterer ikke en liste (`LocalPort 22222,9022` giver "Bad Match condition"; testet med OpenSSH 10.3 2026-10-01). Hver `Match ... LocalPort 22222`-blok kopieres derfor til en identisk blok med `LocalPort 9022` lige efter. Rækkefølgen bevares: specifikke `sftp_<site>`-blokke før default-deny `sftp_*`. Verificeret med `sshd -T -C user=...,lport=9022` mod en kopi af live-strukturen: 9022 giver præcis samme `ForceCommand` som 22222. `grep -q` gør kommandoen idempotent.

`bootout` afbryder igangværende SFTP-overførsler, og Edges prøver selv igen. Socket'en er inetd-agtig, så hver ny forbindelse læser `sshd_config` på ny. sshd'en skal ikke genstartes.

**H3. Verifikation (kan køres af Claude):**

```bash
netstat -an -p tcp | grep -E '\.(9022|9222|22022|22222) .*LISTEN'
nc -w 3 127.0.0.1 9222 </dev/null | head -1   # SSH-2.0-...
nc -w 3 127.0.0.1 9022 </dev/null | head -1   # SSH-2.0-...
ssh-keyscan -p 9222 127.0.0.1 2>/dev/null | ssh-keygen -lf - | grep TwExDmMY   # dedikeret tunnel-nøgle
```

**H4. Router/NAT (Peter):** ✅ udført 2026-10-01: 9022 og 9222 er viderestillet, 22022/22222 beholdes indtil oprydningen (2222 er også viderestillet, men bør fjernes, se Trin R).
Verificér udefra, eller via hairpin fra Headend: `nc -vz backend.timelapse-pro.dk 9222` og `9022`, samt `tunnel.timelapse-pro.dk 9222`.

## Trin E — flyt én Edge ad gangen (Edge1 først)

Edge1: Peter har shell via reverse-SSH.
Edge2 nås fra Headend med `ssh -p 2204 orangepi@127.0.0.1`.
Edge1 svarer til `127.0.0.1:2201`.

**E1. known_hosts for de nye porte (på Edgen).** Kopiér `deploy/edge/add_known_hosts_port.sh` til Edgen, for eksempel med `scp -P 2201 ... orangepi@127.0.0.1:/tmp/`. Kør derefter:

```bash
sudo bash /tmp/add_known_hosts_port.sh tunnel.timelapse-pro.dk 22022 9222
sudo bash /tmp/add_known_hosts_port.sh <sftp_host fra trin 0> 22222 9022
```

Begge skal udskrive `TILFØJET ...` eller `OK: ... findes allerede`.
Udskriver de `FEJL` (exit 1/2), så **stop**: enten lytter Headend/NAT ikke endnu, eller nøglen matcher ikke.

**E2. Tunnel → 9222.**
1. Kontrollér først, at UI-rettelsen fra kode-PR'en er deployet. Den bevarer `fallback`/`extra_forwards`/`strict_host_checking`; den gamle "Gem" smed dem væk.
2. Ret i System Administration → enheden → SSH tunnel → *Primary* til `timelapse_tunnel@tunnel.timelapse-pro.dk:9222`, og gem.
3. Edgen henter konfigurationen over 8443. Den kørende tunnel bliver dog på 22022, indtil den forbindes igen. Tving en ny forbindelse på Edgen:

```bash
sudo systemctl restart timelapse-edge
```

Peters shell via tunnellen ryger her og skal åbnes igen efter cirka 30–60 sekunder, nu via 9222.

**Verificér på Headend:**

```bash
netstat -an -p tcp | grep '\.9222 .*ESTABLISHED'
ssh -p 2201 orangepi@127.0.0.1 hostname
```

**Rollback:** Kommer tunnellen ikke op inden for cirka 3 minutter, så sæt *Primary* tilbage til `...:22022`. Edgen får det over 8443 og forbinder igen på den gamle port.

**E3. Gentag E1–E2 for Edge2** (remote-port 2204).

**E4. SFTP → 9022 (global, alle Edges på én gang).**
1. Når **alle** Edges har `[sftp_host]:9022` i `known_hosts` (E1), sættes `sftp_port` til `9022` i System Administration (eller med psql).
2. Verificér en upload pr. Edge: Edge-loggen og nye filer under `/Volumes/data-fast/timelapse-incoming/...`.
3. **Rollback:** sæt `sftp_port` tilbage til `22222`.

## Trin R — oprydning (tidligst efter cirka 1 uges stabil drift)

- Tunnel-sshd: fjern `Port 22022`, `sshd -t`, `kill -HUP`.
- `ssh-2222.plist`: kun `{"SockServiceName":"9022"}`, derefter bootout/bootstrap. I `sshd_config`: `LocalPort 22222,9022` → `LocalPort 9022`.
- Router: fjern NAT for 22022 og 22222.
- Edges: de gamle `known_hosts`-linjer kan blive liggende. De er ufarlige.
- Fjern den midlertidige NAT, som Peter lavede 2026-10-01. **2222 skal heller ikke viderestilles**: intet TimeLapse lytter dér, og porten er reserveret til en anden applikation. Den kan fjernes med det samme.

## Separat fund (ikke del af portflytningen)

Den live `/etc/ssh/sshd_config` har **ingen** `Match User sftp_* LocalPort 22`-blok, som afviser site-upload-brugere på admin-SSH (port 22). Hardening-profilen `deploy/ssh/timelapse-sshd-sftp.conf` kræver den, og `deploy/PORTS.md` siger, at `sftp_*` ikke må kunne logge ind på 22.
`sshd -T` mod live-strukturen giver `forcecommand none` for `sftp_*` på port 22.
Om login reelt er muligt afhænger af brugernes shell/adgangskode og skal verificeres. Registreres som GRC-fund og håndteres separat.
